# Праздничные орбиты ST VILLAGE

Первый этап: зима (20 декабря–10 января), космос (10–12 апреля), Хэллоуин (25 октября–1 ноября). Даты ежегодные, включительно, по Москве; текущее время берётся с устройства посетителя. Вне этих окон сайт обычный.

## Где смотреть и управлять

- Локально: запустить обычный `pnpm dev`, открыть `/preview/holidays`. В используемой при разработке сессии сервер работает на `http://127.0.0.1:4173/preview/holidays`.
- На dev после разрешённого push/deploy: `https://dev.stvillage.ru/preview/holidays`, за существующей защитой стенда. Предпросмотр не меняет календарь и сохранённый выбор посетителя.
- На production main маршрут закрыт (404), даже с поддельными Host-заголовками. Публичных ссылок и записи в sitemap нет, preview получает noindex.
- Переключатель «Праздничное оформление» в подвале доступен всегда. Выбор сохраняется в localStorage (`st-holiday-effects`) и синхронизируется между вкладками. Отказ storage не ломает переключатель.

На главной — сезонная иллюстрация и ограниченное количество частиц; на других публичных страницах — только небольшой акцент у логотипа. На `/status/management` декора нет. На ширинах 681–1279 px боковые частицы скрыты из-за узких полей, иллюстрация остаётся. Уменьшение движения даёт статичное оформление, высокая контрастность скрывает декор. Скрытая вкладка останавливает движение, включая preview.

## Как менять календарь

Правила — `src/features/holidays/calendar.ts`, чистый resolver — там же. Правило задаёт id, имя, начальную/конечную пару месяц–день, тему, приоритет и enabled. Новая визуальная тема требует отдельного renderer, стилей и проверок; добавление даты к существующей теме не требует новой архитектуры. Одновременно выбирается одно событие, наибольший приоритет; при равенстве — ASCII-id. Для временного отключения всех тем достаточно отдельным коммитом выключить три enabled, затем штатно развернуть его.

## Проверки

`pnpm release:check` включает сборку, lint, typecheck, бюджет изображений, серверные и модульные тесты, включая `tests/holiday-calendar.test.mjs`. `pnpm test:visual` проверяет desktop/mobile и сравнивает снимки. Новые эталоны добавлены отдельно; прежние не заменены.

Итоговая локальная проверка 18 октября 2026: 44 серверных + 34 модульных + 78 браузерных = 156 тестов, все проходят. Отдельно проходят ESLint, TypeScript, production build и бюджет изображений. Вторая production-сборка с доверенным dev URL дала preview 200 + noindex; обычная main-подобная сборка возвращает 404, в том числе при поддельных заголовках. Затем восстановлена обычная локальная сборка. Push/deploy на VPS не выполнялись.

Проведено независимое ревью. Подтверждённое перекрытие текста боковыми частицами и отсутствие паузы в скрытом preview исправлены с RED→GREEN регрессионными проверками. Проверки работают в Chromium; другие движки и реальный многодневный сон ОС отдельно не проверялись. Дополнительный provider mount/unmount harness и точный клиентский переход на `/status/management` остаются улучшением тестового покрытия, не подтверждённой ошибкой продукта.

## Решения при выполнении

1. Использован существующий checkout dev по запросу пользователя, без нового worktree. Цена решения — меньше изоляции; компенсируется адресным staging.
2. Bash-помощник учёта работ не обрабатывал Windows drive path; его остановили, учёт продолжили вручную через apply_patch. Цена — ручная дисциплина ведения записей; ограничения доступа не обходились.
3. Связанные UI-задачи объединены в один проверенный коммит. Цена — более крупный шаг отката.
4. В старых тестах сохранены уже фиксированные непраздничные даты, завязанные на данные мониторинга. Цена — несколько контрольных дат вместо одной.
5. Пауза скрытого preview признана обязательной частью общей политики видимости, а не необязательной полировкой. Цена — небольшая подписка preview на существующий context.
6. Реальный push/deploy и проверка авторизации стенда требуют отдельного подтверждения. Локальный результат не доказывает состояние удалённого сервера.
7. Реальные проверки других браузерных движков и длительного сна ОС не заменены предположениями. Риск — возможные специфические для среды ошибки.

Основной сайт, партнёрские ссылки, бот, тарифы, новости и настройки VPS этой разработкой не меняются. Версия приложения не повышается до согласованного выпуска.
